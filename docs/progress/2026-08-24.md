- Movie List / Search. Complete. `MoviesController` (`GET /api/movies` with title-prefix/genre/director/year filters, offset pagination fixed at 100/page, page validation against total pages; `GET /api/movies/page-count` via `sys.partitions` metadata instead of a table scan; `GET /api/movies/{id}`) backed by 31 xUnit tests against EF Core InMemory. `HomePage.tsx` wired to the real search API with pagination controls, 5 Vitest+RTL tests.
- Movie Detail View. Complete. `ReviewsController` (`GET`/`POST /api/movies/{movieId}/reviews`, one review per user per movie enforced with a 409, JWT-authenticated create) covered by the same 31-test suite. `MovieDetailPage.tsx` renders movie detail + paginated review list + a login-gated review submission form, 6 Vitest+RTL tests.

## Blockers
None currently open. Two real bugs were found and fixed during live verification against the actual containerized SQL Server (not caught by the InMemory-backed unit tests, by design — see Lint/test status): `SqlMovieCountProvider` read SQL Server's `SUM()` result as `int` when it's actually `bigint` (threw `InvalidCastException` on every real call); `ReviewsController`'s review-list query projected through a required navigation (`r.User!.UserName!`), which EF compiles to an INNER JOIN — any review whose `UserId` doesn't resolve to a real `AspNetUsers` row (which is exactly what this schema's own seed data in `CriticalViewerDB.sql` looks like) was silently dropped from the page even though it was correctly counted in `totalCount`. Both are fixed, covered by a new regression test, and reverified live.

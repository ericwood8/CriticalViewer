# Progress - 2026-08-25

- Account Creation. In progress. `POST /api/auth/register` works end-to-end; no dedicated test file yet, no frontend signup page, and there's still no `/api/auth/login` endpoint for returning visitors.
- Password Change. In progress. `POST /api/auth/change-password` exists and is `[Authorize]`-gated; no tests, no frontend account view.
- Movie List / Search. Complete, plus one addition beyond the original 4-feature scope. Fixed a real bug found during live UI testing: the `year` filter was silently defaulting to the current year even when left blank, so there was no way to search across all years and "leave everything blank" only ever returned that year's movies — `year` is now a plain optional filter, matching title/genre/director. Also added `POST /api/movies` (any logged-in user can add a movie, same trust level as leaving a review — no admin role exists in this app) with a new `AddMoviePage.tsx` UI, gated behind login, reachable via a new "Add Movie" nav link. Added 250 synthetic movies under a dedicated year (2099) to `CriticalViewerDB.sql` so 100-item pagination can actually be exercised end to end.
- Movie Detail View. Complete. Fixed the "Browse" nav link doing nothing when already on the home page (React Router doesn't remount an element for a same-path navigation by default) — `HomePage` is now keyed on `location.key` so it resets on every "Browse" click.

## Blockers
None currently open. One environment-level gotcha worth flagging for future frontend work: Docker Desktop on Windows doesn't reliably forward file-change events from the bind-mounted `frontend/` directory into the `frontend_ui` container, so Vite's dev server was silently serving stale code after edits. Fixed by switching Vite to polling mode (`vite.config.ts`) — future edits should hot-reload normally now, but if a frontend change ever appears not to take effect in the container, a `docker compose restart frontend_ui` is the fallback.

## Lint / test status
Backend and frontend suites both green: `dotnet format --verify-no-changes` clean, `dotnet test` 37/37 (up from 32 — added movie-creation coverage), `npm run lint` clean, `npm test` 23/23 (up from 19 — added `AddMoviePage` coverage). All of today's fixes were also verified live against the running `docker compose` stack, not just the test suites: cleared-year search now returns all 262 movies, the 2099 pagination batch correctly splits 100/100/50 across pages, Browse resets the search from any state, and a movie was created through the actual UI form and landed correctly in the database.

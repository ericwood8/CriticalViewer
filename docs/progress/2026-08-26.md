## Database engine: SQL Server → MySQL

Migrated the whole backend off SQL Server onto MySQL, driven by AWS cost: Lightsail Container Service has no persistent storage (a redeploy wipes any database run as a container there), and RDS SQL Server pricing (~$150-250+/mo estimated) made "just run SQL Server as a Lightsail container and eat the data loss" a real short-term option — but Lightsail's own Managed Database product supports MySQL/PostgreSQL, not SQL Server. Migrating the app to MySQL unlocks that: real persistence at ~$15-25/month combined (Lightsail Managed Database + a small Container Service tier) instead of $80+/month for something that still isn't persistent.

Changed:
- EF Core provider: `Microsoft.EntityFrameworkCore.SqlServer` → `Microting.EntityFrameworkCore.MySql` (a community fork of Pomelo tracking .NET's release cycle — upstream Pomelo hasn't shipped an EF Core 10 release yet; verified the fork is a legitimate, actively-maintained drop-in before using it)
- `SqlMovieCountProvider`: `sys.partitions` → MySQL's `information_schema.TABLES.TABLE_ROWS` for the same fast, scan-free row count
- `CriticalViewerDB.sql`: fully rewritten in MySQL dialect (T-SQL syntax, `UNIQUEIDENTIFIER`→`CHAR(36)`, `NVARCHAR`→`VARCHAR`, `DATETIME2`→`DATETIME`, covering-index `INCLUDE` dropped since MySQL/InnoDB has no equivalent, idempotency pattern switched from `IF NOT EXISTS`-guarded blocks to `INSERT IGNORE` against unique constraints where possible)
- `docker-compose.yml`: `database`/`db_seed` services now run `mysql:8.4` (the Docker Official Image) instead of SQL Server
- Regenerated the EF migration against MySQL (Identity tables only — Movies/Reviews are still owned by the SQL script, not EF, same design as before)
- Connection strings and local dev instructions updated (MySQL has no Windows Integrated Auth equivalent — username/password now, everywhere)
